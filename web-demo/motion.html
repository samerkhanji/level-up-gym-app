Motion system

The one set of durations, easings and patterns every dashboard uses. Motion here communicates state and direction — it never delays an action, traps focus, or survives a reduced-motion preference.
Tokens — defined once, used everywhere
:root {
  --motion-instant: 80ms;    /* button press */
  --motion-fast: 140ms;      /* hover, focus, chips */
  --motion-standard: 220ms;  /* cards, drawers, modals */
  --motion-slow: 320ms;      /* page transitions (max) */
  --ease-standard: cubic-bezier(.2, .8, .2, 1);
  --ease-enter:    cubic-bezier(.2, .9, .2, 1);
  --ease-exit:     cubic-bezier(.4, 0, 1, 1);
}

Button lifecycle — the action fires immediately, motion only reports it
Rest state
Rest → pressed (80 ms scale) → loading (spinner, the only infinite animation and it stops) → success check (< 500 ms) → enabled again. Double-clicks during loading are ignored by state, not by animation.
Modal & drawer — focus managed, stacking impossible
Focus moves into the dialog on open and returns to the trigger on close; Esc and the backdrop close it; background scroll locks while open and always unlocks. One overlay element is toggled — rapid clicking can never stack backdrops, trap focus or leave invisible layers.

The new label is readable immediately; the card never disappears before the employee understands the result; double-click protection lives in state logic, independent of the animation.
Toast queue — one action, one toast
Repeated triggers update the single toast in place instead of stacking five. Notifications never cover primary actions (top-center, auto-dismiss).
Loading — skeletons that actually stop
Shimmer runs only while genuinely loading and is removed on completion — no permanent GPU work, no stuck loading states (a timeout fallback always resolves the UI).
Reduced motion — a preference, not a suggestion
Following your system preference 
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
With motion reduced, every state above still communicates through text, icons and colour-independent labels — success, failure, loading and status changes never rely on movement alone. No parallax, floating, spinning backgrounds or ambient pulsing anywhere in the system.
Do / don't
Do — transition: transform 220ms var(--ease-standard), opacity 180ms var(--ease-standard);
Don't — transition: all 500ms; · multi-second interface animation · hover-only feedback · motion that moves keyboard focus · continuous animation outside genuine loading/recording states.
